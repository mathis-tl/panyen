SPEC ACTIVE — 1.4 : DIFFÉRENTIEL ALIMENTAIRE DEPUIS L'ECSP 2022
DESTINATAIRE — Cursor Agent

OBJECTIF UTILISATEUR
Calculer, mois par mois depuis avril 2022, si l'écart alimentaire mesuré entre la
Martinique et la France métropolitaine se creuse ou se resserre. Le calcul doit
partir du dernier lot IPC métropolitain complet, comparer uniquement des évolutions
intra-territoire et nommer explicitement toute extrapolation de l'ECSP "estimation".

ÉTAT ET DÉCISIONS VALIDÉES
- La spec 1.3b est terminée au commit `8319055`.
- `stg_ipc` contient le lot historique France entière et le lot actif France
  métropolitaine, distingués par `perimetre_reference`.
- Le calcul utilise exclusivement le fichier entier le plus récent dont le
  périmètre est `france_metropolitaine`. Ne jamais choisir un snapshot différent
  par territoire, idbank ou mois.
- Avril 2022 (`2022-04-01`) est l'ancre commune, alignée sur l'ECSP menée en
  mars-avril 2022.
- L'ECSP alimentaire mesure un écart de Fisher de +40 % entre la Martinique et la
  France métropolitaine. Cette mesure est saisie dans un seed dbt sourcé.
- Architecture retenue : SQL DuckDB, seed dbt, unit tests dbt natifs et data tests
  dbt. Les versions verrouillées suffisent ; aucune dépendance ni macro maison.
- Rebaser d'abord en format long à l'intérieur de chaque territoire, puis apparier
  les facteurs d'évolution. Ne jamais placer deux niveaux d'indice territoriaux
  dans une soustraction, un ratio ou une comparaison.

FORMULES OBLIGATOIRES
Pour chaque territoire `x` et chaque mois `t`, calculer d'abord uniquement dans la
série de ce territoire :

`facteur_x(t) = indice_x(t) / indice_x(2022-04)`

`evolution_x_pct(t) = (facteur_x(t) - 1) * 100`

Après ce rebasage intra-territoire seulement, apparier les mois et calculer :

`differentiel_evolution_points(t) = evolution_martinique_pct(t) - evolution_france_metropolitaine_pct(t)`

`coefficient_ecart(t) = facteur_martinique(t) / facteur_france_metropolitaine(t)`

`ecart_prix_estime_pct(t) = ((1 + 40 / 100) * coefficient_ecart(t) - 1) * 100`

À l'ancre : les deux facteurs valent 1, les deux évolutions et le différentiel
valent 0, le coefficient vaut 1 et l'écart vaut la mesure ECSP de 40 %. Pour les
mois postérieurs, `ecart_prix_estime_pct` est toujours une estimation. Ne pas
remplacer le coefficient exact par la seule différence des pourcentages d'évolution.

TDD ET UNIT TESTS OBLIGATOIRES
- Commencer par un unit test dbt rouge sur
  `int_ipc_alimentation_rebase` avec des lignes synthétiques minimales ; montrer
  l'échec avant de créer le modèle.
- Utiliser les unit tests natifs dans un YAML sous `dbt/models/`, avec des entrées
  `ref()` explicites et des alias de tables dans le SQL lorsque dbt l'exige.
- Couvrir au minimum :
  1. deux snapshots métropolitains et un lot historique : seul le fichier actif le
     plus récent est pris, en entier ;
  2. bord irrégulier : un mois terminal présent pour un seul territoire est exclu et
     `dernier_mois_commun` reste explicite ;
  3. mois interne absent et observation `ND` : la ligne calendaire subsiste avec un
     calcul nul afin que les data tests échouent, sans interpolation ;
  4. ancre absente ou nulle : aucun facteur valide n'est fabriqué ;
  5. calcul synthétique simple : facteurs, deux évolutions, différentiel,
     coefficient exact et estimation ECSP attendue ;
  6. ligne d'ancre : facteurs 1, évolutions 0, différentiel 0, coefficient 1,
     `ecart_prix_estime_pct = 40` et `nature_ecart = mesure_ecsp_2022`.
- Les valeurs de fixtures sont explicitement synthétiques. Elles ne doivent jamais
  être documentées ou présentées comme des données Insee.

DATA TESTS OBLIGATOIRES

- Le lot sélectionné est unique, métropolitain, le plus récent et contient seulement

- `nature_ecart` n'accepte que `mesure_ecsp_2022` et
  `estimation_a_partir_ecsp_2022`, avec la première valeur uniquement à l'ancre.

INVARIANTS MÉTHODOLOGIQUES
- Toute comparaison en niveau entre l'indice D972 et l'indice FM est un bug bloquant.
- Chaque ratio d'indice est calculé à l'intérieur d'un seul territoire avant toute
  jointure territoriale.
- Seul le +40 % de l'ECSP 2022 est une mesure de niveau. Chaque valeur extrapolée
  après l'ancre est nommée `ecart_prix_estime_pct` et étiquetée estimation.
- Le fichier actif est sélectionné comme une unité indivisible ; aucun mélange de
  snapshots n'est autorisé.
- La provenance survit jusqu'à la fact table : idbanks, fichier brut, collecte UTC et
  source ECSP.
- Aucun mois absent ou `ND` interne n'est filtré, interpolé, reporté ou réparé.
